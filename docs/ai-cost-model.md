# Экономика AI: сколько реально стоит раунд

Документ отвечает на два вопроса: сколько стоит запуск и где деньги утекали.
Цены проверены 2026-08 и живут в коде в одном месте: `apps/api/src/lib/pricing.ts`.

---

## Что стоит один раунд

Раунд = 3 хода оппонента + 1 вызов судьи. Модель одна, Claude Haiku 4.5 через
OpenRouter ($1 / $5 за MTok).

| Статья | До | После | Что изменилось |
|---|---|---|---|
| LLM, оппонент ×3 | ~$0.008 | ~$0.006 | окно истории вместо полного транскрипта, 300 токенов вместо 350 |
| LLM, судья ×1 | ~$0.009 | ~$0.007 | 900 токенов вместо 1200, короткие comment |
| Суммаризатор | +1 вызов на ход | удалён | сжимал 600 токенов ценой отдельного вызова, то есть работал в убыток |
| STT, 3 минуты речи | $0.0056 (large-v3) | $0.0020 (turbo) | `whisper-large-v3-turbo`, в 2.8 раза дешевле при том же WER на русском |
| TTS, 3 реплики | $0.036 (800 симв.) | $0.019 (420 симв.) | `TTS_MAX_CHARS` урезан вдвое |
| **Итого текст + голосовой ввод** | **$0.023** | **$0.015** | |
| **Итого с озвучкой оппонента** | **$0.059** | **$0.034** | |

Главный вывод не поменялся: **озвучка дороже всего остального вместе взятого.**
Одна реплика оппонента в 420 символов стоит больше, чем ход модели, который её
придумал. Если бюджет ограничен, TTS выключается первым, и продукт от этого
почти не теряет: голос заявлен как способ ВВОДА.

## Пилот

Из расчёта 8 раундов на ученика.

| | текст + голосовой ввод | с озвучкой |
|---|---|---|
| 50 учеников (400 раундов) | ~$6 | ~$14 |
| 100 учеников (800 раундов) | ~$12 | ~$27 |

Закладывай ×2 на ретраи, смоки и ночные eval-прогоны судьи. Депозита $20 на
OpenRouter хватает на текстовый пилот со сотней школьников.

## Где деньги утекали

### 1. STT и TTS не считались вообще

Суточный бюджет читался из `DebateRound.costEstimateUsd`, куда попадали только
вызовы LLM. У `/voice/stt` и `/voice/tts` был единственный барьер: rate limit
20 запросов в минуту. При `TTS_PROVIDER=openai` и лимите 800 символов это
**~$14 в час с одного аккаунта**, просто дёрганьем эндпоинта в цикле.

Починено: таблица `usage_events`. Каждый платный вызов (LLM, STT, TTS) пишет
строку с провайдером, моделью, единицами и стоимостью. Суточный лимит считается
по ней.

### 2. Лимит проверялся после траты, а не до

`assertDailyBudget` смотрел на уже потраченное. Значит последний вызов всегда
уходил за потолок. Теперь проверяется `потрачено + проектная стоимость вызова`,
и для TTS это точная величина: символы известны заранее.

### 3. `DAILY_COST_LIMIT_USD = 1.0` не срабатывал никогда

В текстовом режиме 10 раундов стоят $0.15, поэтому раньше упирался
`DAILY_ROUND_LIMIT`, а денежный кап был декоративным. Опущен до **$0.25**:
теперь это настоящий предохранитель, а не украшение.

### 4. Prompt caching был выключен физикой

`cacheSystem: true` у судьи ничего не делал: Anthropic начинает кэшировать от
~2048 токенов промпта, а системный промпт судьи весит ~800. Флаг снят, чтобы не
создавать иллюзию экономии. Механизм в провайдере оставлен на случай, когда
промпты дорастут.

### 5. Суммаризатор

Он тратил отдельный вызов LLM, чтобы сжать ~600 токенов истории. При трёх
обменах это чистый убыток. Заменён на окно: последние `HISTORY_WINDOW_TURNS`
реплик, каждая обрезана до `HISTORY_TURN_MAX_CHARS`. Ноль вызовов, тот же эффект.

---

## Ручки, которыми это крутится

| Переменная | Дефолт | Смысл |
|---|---|---|
| `DAILY_COST_LIMIT_USD` | `0.25` | суточный потолок в деньгах на одного ученика |
| `DAILY_ROUND_LIMIT` | `10` | суточный потолок в раундах |
| `DAILY_TTS_CHARS_LIMIT` | `4000` | суточный потолок символов озвучки |
| `DAILY_STT_SECONDS_LIMIT` | `900` | суточный потолок секунд распознавания |
| `TTS_MAX_CHARS` | `420` | потолок одной озвучки |
| `GROQ_STT_MODEL` | `whisper-large-v3-turbo` | модель распознавания у Groq |
| `HISTORY_WINDOW_TURNS` | `4` | сколько последних реплик уходит в промпт |
| `HISTORY_TURN_MAX_CHARS` | `700` | обрезка одной реплики в истории |

## Что смотреть после запуска

```sql
-- Куда реально уходят деньги за сутки
SELECT kind, provider, model, count(*), round(sum(cost_usd), 4) AS usd
FROM usage_events
WHERE created_at >= date_trunc('day', now())
GROUP BY 1, 2, 3
ORDER BY usd DESC;

-- Топ прожигателей бюджета
SELECT user_id, round(sum(cost_usd), 4) AS usd
FROM usage_events
WHERE created_at >= now() - interval '7 days'
GROUP BY 1 ORDER BY usd DESC LIMIT 20;
```

Если в первой выборке `TTS` стоит выше `LLM_JUDGE`, продукт платит за красоту,
а не за обучение. Это сигнал урезать `TTS_MAX_CHARS`, а не докупать баланс.
